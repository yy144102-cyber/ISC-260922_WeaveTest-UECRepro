## 0. このプログラムがやること

ホームから母材の上の開始点へ移動し、三角波のウィービングで直線のビードを1本引く。
層ごとに Z を上げ、往路と復路を交互に繰り返して壁を積む。最後に上へ逃げてホームへ戻る。

```
ホーム ─PTP→ 退避位置 ─LIN→ 開始点（ここで完全に止まる）
                               │
          ┌────────────────────┘
          ▼
   ┌─ 層ループ（WB_numLayers 回）─────────────────────────────────┐
   │  進む向きを決める（層番号から計算）                             │
   │  W3D に層番号を渡す                                             │
   │  RSI を ON → アークを ON（WB_dryRun = FALSE のときだけ）        │
   │  造形速度に切り替え、ウィービング 62 周期                        │
   │  アークを OFF（同上）→ RSI を OFF                               │
   │  位置決め速度に戻し、層の終わりの位置を記録                      │
   │  （最終層以外）                                                  │
   │    一時停止が有効で、この層が指定の層なら:                       │
   │      上へ逃げる → 退避位置 → ホーム → HALT                      │
   │      スタートで: 退避位置 → 層の終わりの真上 → 層の終わり       │
   │    Z を上げて待つ                                                │
   └──────────────────────────────────────────────────────────────┘
          │
          ▼
   上へ 50 mm 逃げる ─PTP→ 退避位置 ─PTP→ ホーム
```

## 1. 2つのファイルの役割

| ファイル | 入っているもの | 実行中に変わるか |
|---|---|---|
| `.dat` | オペレータが調整する値（区画1）と、ティーチした点・ArcTech のデータ（区画2） | 区画1 と教示点は変わらない（S2）。**例外: `WDAT1`**（下記） |
| `.src` | 手順と、実行中に計算する値 | 計算した値は、プログラムが動いている間だけ存在する |

**`.dat` に経路の座標は入っていない。** 経路は `.src` の中で、`.dat` の値から毎回計算する（S3）。
ウィービングの幅や進み量を変えたいときは `.dat` の値を1つ変えれば、経路全体がそれに従う。
その代わり、`.dat` を見ても経路は分からない。`.src` にあるのは式だけで、実際の数値は実行して初めて入る。

**例外の `WDAT1`**: ArcTech の溶接データ。`.src` の冒頭で、区画1 の溶接条件（`WB_synergicLine` など）から毎回上書きする。
オペレータは `WDAT1` を直接触らず、区画1 の値を変える（`.dat` のコメントにも書いてある）。

## 3. `.dat` の値

| 変数 | 値 | 意味 |
|---|---|---|
| `WB_toolNo` | 1 | ツール番号（トーチの TCP）。負荷は同じ番号の `LOAD_DATA[1]` が使われる |

| `WB_ptpAccPct` | 100 | % | 同じく加速度 |

#### CP（直線）の速度（`;--- CP dynamics ---`）

| 変数 | 値 | 単位 | 現場の単位 | 使いどころ |
|---|---|---|---|---|
| `WB_approachMPerSec` | 0.1 | m/s | 6000 mm/min | 溶接していないときの直線動作（開始点への移動、層送り、逃げ） |

## 4. `.src` の流れ

### 4-1. ヘッダ

`&ACCESS` と `&REL` は制御盤とエディタが管理する行で、手で変えない（V6）。
`DEF WBead_20260924( )` がプログラムの始まり。名前はファイル名と同じにする（N12）。

続くコメントには、動作に関係しない次のことが書いてある。

| 見出し | 中身 |
|---|---|
| `VERSION` / `VERIFIED` | 版と検証の段階（T8）。**2026-09-25 の造形の前のまま**で、段階 6〜7（アークを出した造形）は「not yet」と書かれている。実際には 1 / 4 / 10 / 116 層を造形した |
| `PHASES` | 段階ごとの `WB_numLayers` と `WB_dryRun` |
| `ARC` / `RSI` / `PAUSE` | それぞれの動き（§4-8） |
| `RESTART POLICY` / `RESTART CAUTION` | 中断した造形の再開の手順と注意（§4-9） |

### 4-2. 変数の宣言（`;--- declarations ---`）

KRL は、実行する文より前に宣言を書く決まりがある。

| 変数 | 型 | 用途 |
|---|---|---|
| `layerIdx` / `cycIdx` / `axisIdx` | INT | 層・周期・軸のカウンタ |
| `passPlus` | BOOL | この層が + 向きに進むか |
| `fwdQuarterRise` / `fwdHalfFall` | FRAME | + 向きの層で使う2種類の変位 |
| `revQuarterRise` / `revHalfFall` | FRAME | − 向きの層で使う同じもの |
| `quarterRise` / `halfFall` | FRAME | 今の層で使う組（上のどちらかを写す） |
| `layerStep` / `lift` | FRAME | 層を上げる変位 / 上へ逃げる変位 |
| `layerEndPos` / `aboveEndPos` | E6POS | 層の終わりの位置 / その真上（一時停止から戻るとき） |

`FRAME` は X Y Z A B C の6成分だけを持つ（S/T を持たない）。**ここでは位置ではなく「どれだけ動くか」の変位として使う。**
ループの変数に `i` を使わないのは、W3D のグローバル配列 `I[]` とぶつかるため（KRL は大文字と小文字を区別しない。N8）。

### 4-3. INI（`;FOLD INI`）

KUKA のテンプレートが入れる定型。停止メッセージが出たら `IR_STOPM` を呼ぶ割り込みを登録し、`BAS(#INITMOV,0)` で動作パラメータを初期化する。
このプログラムは `BAS(#INITMOV,0)` が入れた値に頼らない。直後で、使う値を全部自分で入れ直す（M2）。

### 4-4. 動作パラメータ（`motion parameters`）

**座標系（`;--- frames ---`）**

```krl
FDAT_ACT.TOOL_NO   = WB_toolNo
FDAT_ACT.BASE_NO   = WB_baseNo
FDAT_ACT.IPO_FRAME = #BASE
BAS (#FRAMES, 0)
```

ツール番号とベース番号を `FDAT_ACT` に入れ、座標系の組み立ては KUKA 標準の `BAS(#FRAMES)` に任せる。
**`$BASE = BASE_DATA[17]` と直接書いてはいけない。** Base[17] はポジショナに割り当てられていて、`BAS` はこれを `EK(ポジショナの根元, #EASYS, BASE_DATA[17])` と組み立てる。直接代入するとこれが抜け、`BASE_DATA[17]` の中身（ポジショナのフランジからのずらし量 Z 310.8 mm）を**ロボット自身の根元から**測った位置を指してしまう（実機の `bas.src` で確認）。
`BAS` は `$LOAD`（ツールと同じ番号の負荷データ）と、smartPAD に表示される現在のツール・ベースも更新する。

**溶接条件を `WDAT1` へ（`;--- weld conditions -> WDAT1 ---`）**

区画1 の溶接条件と `WB_tsMPerSec` を `WDAT1` の点弧（Strike）・溶接（Weld）・クレータ（Crater）に書き込む。
`WB_ArcOn` の中の TRIGGER は先行実行（§4-4 の `$ADVANCE`）の中で `WDAT1` を読むので、**最初の動作命令より前**に置く必要がある。

**PTP と CP の速度**

`$VEL_AXIS[1..6]` / `$ACC_AXIS[1..6]` に PTP の割合を、`$VEL.CP` などに直線動作の速度を入れる。
`$VEL` は構造体なので `{CP 0.1, …}` と1行でも書けるが、その書き方は `{ }` の中に変数を書けない（S10）。`.dat` の値を使うために成分ごとに代入している。
**DryRun で AUT のときに A4 の速度超過が出たのは、この CP の設定が無かったため**（`BAS(#INITMOV,0)` の初期値のまま LIN が走った）。

**近似（`$APO.CDIS`）**

`C_DIS` を付けた動作は、終点の 1 mm 手前から次の動作へ滑らかにつなぐ。ウィービングの折り返しで止まるとビードが不均一になるため。
**そのため実際の TCP は ±7.5 mm の頂点を通らず、角が少し丸まる。**

**相対動作と先行実行（`$ROTSYS` / `$ADVANCE`）**

```krl
$ROTSYS  = #BASE
$ADVANCE = 3
```

- `$ROTSYS`: `LIN_REL` で姿勢を相対的に回すときの基準の座標系。今の変位は A/B/C がゼロなので結果は変わらないが、既定に頼らず明示している（C7）
- `$ADVANCE`: 制御盤が、実行中の命令より何本先まで読んで経路を計画するか。1〜5、既定 3。**近似（`C_DIS`）にはこれが要る。** 計画が間に合わないと、`LIN_REL` は角を丸めずにそこで完全に止まる（エラーは出ない）。段階 5（AUT、100 %、116 層）は 3 で動いた。ウィービングが角で止まるようなら 5 を試す
- `$ADVANCE` を `.dat` に置かないのは、オペレータが触る造形の値ではなく、制御盤の設定だから（2026-09-25 に `WB_advance` を廃止）

### 4-5. 経路の計算（`derived values`）★

**ここで `.dat` の値からウィービングの経路を組み立てる。** 計算はこの1か所だけ（S3）。

1周期を上から見た図（コードのコメントと同じ）:

```
         1              上端（+振幅）
        / \
       0   \   3        中心（3 は次の周期の 0）
            \ /
             2          下端（−振幅）
       |<-step->|       ---> + 向きに進む
```

| 区間 | 変位 | 進む軸 | 横（振る軸） | 動き |
|---|---|---|---|---|
| 0 → 1 | `quarterRise` | +step/4 = **+1.0** | +振幅 = **+7.5** | 中心 → 上端 |
| 1 → 2 | `halfFall` | +step/2 = **+2.0** | −2 × 振幅 = **−15.0** | 上端 → 下端 |
| 2 → 3 | `quarterRise` | +1.0 | +7.5 | 下端 → 中心 |

- 「上り / 下り（rise / fall）」は図の上下のことで、**Base[17] の X/Y 平面の中の横方向**。Z ではない（Z の動きは `layerStep` と `lift`）
- 2 → 3 と、次の周期の 0 → 1 は同じ変位なので、下端から上端までは中心で分かれた1本の直線になる。そこには角が無いので、`C_DIS` で経路は変わらない
- 1周期の合計: 進む軸 1.0 + 2.0 + 1.0 = **4.0**（= `WB_weaveStepMm`）、横 +7.5 − 15.0 + 7.5 = **0**、経路の長さ 7.566 + 15.133 + 7.566 = **30.265 mm**
- `WB_progAlongY = TRUE` なので、「進む軸」は Y、「横」は X

**+ 向き（fwd）と − 向き（rev）の組を、最初に両方作っておく。** rev は横の値が同じで、進む軸の値だけ符号が逆。
層ごとに符号を反転する処理が要らず、「今どちら向きか」という状態を持たずに済む（P3、S4）。

最後に、層を上げる変位 `layerStep`（Z +1.40）と、上へ逃げる変位 `lift`（Z +50.0）を作る。
**A/B/C はすべてゼロなので、ウィービング中にトーチの姿勢は変わらない。** 位置だけが動く。

### 4-6. 開始点までの移動（`motion` の最初）

```krl
PTP WB_posHome
PTP WB_posRetract
LIN WB_posStart
```

1. `PTP WB_posHome`: プログラムの最初の動作は、全成分を指定した PTP でなければならない（M4）。これで軸の配置（S/T）が決まる
2. `PTP WB_posRetract`: ホームから Z を 300 mm 下げる。**DryRun ではここを LIN で動かし、AUT で A4 の速度超過が出た**ので PTP にしてある。PTP は各軸の速度の範囲内で動くので、軸の速度超過が起きない
3. `LIN WB_posStart`: 開始点まで直線で動く。近似を付けていないので、**開始点で完全に止まる**（点弧には静止が要る）

### 4-7. 層ループ（`FOR layerIdx = 1 TO WB_numLayers`）

#### a. 進む向きを決める

```krl
passPlus = WB_firstPassPlus
IF ((layerIdx / 2) * 2) == layerIdx THEN
   passPlus = NOT passPlus
ENDIF
```

偶数の層なら向きを反転する。`WB_firstPassPlus = FALSE` なので、1層目は −Y、2層目は +Y、3層目は −Y……となる。

偶数の判定に `MOD` を使わないのは、KSS 8.7 の説明書の演算子の一覧に `MOD` が無いため（受け付けられるかは未確認）。INT 同士の割り算は小数点以下を切り捨てるので、偶数のときだけ元の値に戻る。

| layerIdx | `/ 2` | `* 2` | 元と同じか | 偶数か |
|---|---|---|---|---|
| 1 | 0 | 0 | 違う | 奇数 |
| 2 | 1 | 2 | **同じ** | 偶数 |
| 3 | 1 | 2 | 違う | 奇数 |

向きは**層番号から毎回計算する**。前の層の状態を引き継がないので、途中の層から再開しても向きが狂わない（S4）。

続けて、+ 向きなら fwd の組、− 向きなら rev の組を `quarterRise` / `halfFall` に写す。

#### b. W3D に層番号を渡す

```krl
I[1]        = layerIdx
oLayerNum   = layerIdx
oSideNum    = WB_sideNum
oLayerType  = WB_layerType
oLayerIndex = WB_layerIndex
```

ISC の `WVDepositionMaster.src` と同じ呼び方。何に使われているか（W3D の PC が読んでいるのか）は分かっていない。
これは普通の代入なので、先行実行の中で処理される。1層目では、ロボットが開始点に着く前に値が入る可能性がある。

#### c. RSI とアークを ON

```krl
WAAM_RSI_ON( )
IF NOT WB_dryRun THEN
   WB_ArcOn( )
ENDIF
```

- **RSI はアークの外側で ON / OFF する**（ISC の `WVDepositionMaster` と同じ順）。RSI が立ち上がるのにかかる時間を、アークを出したまま止まっているトーチの上ではなく、点弧の前に使うため
- RSI は W3D の PC（WAAMCtrl）とデータをやり取りするだけで、**経路は補正しない**。空走行でも動く。モード T1 では層ごとに「Caution - sensor correction is activated!!!」が出るが、正常
- `WB_ArcOn` は ArcTech の ARC ON（§4-10）

#### d. ウィービング

```krl
$VEL.CP = WB_tsMPerSec

FOR cycIdx = 1 TO WB_cyclesPerPass
   LIN_REL quarterRise C_DIS #BASE
   LIN_REL halfFall    C_DIS #BASE
   LIN_REL quarterRise C_DIS #BASE
ENDFOR
```

**実際にビードを引く部分。** 1周期 3 本 × 62 周期 = 186 本の直線動作。

| 要素 | 意味 |
|---|---|
| `LIN_REL` | 今いる位置から、指定した変位だけ直線で動く |
| `C_DIS` | 終点で止まらず、1 mm 手前から次の動作へつなぐ |
| `#BASE` | 変位の X/Y/Z を Base[17] の軸の向きで読む |

相対動作なので S/T は要らない（出発点が今の軸の角度そのもの。C3）。
1周期 30.265 mm ÷ 66.7 mm/s ≒ 0.45 秒、1層で約 **28 秒**。

#### e. アークと RSI を OFF、位置決め速度に戻す

`WB_ArcOff`（`WB_dryRun = FALSE` のときだけ）→ `WAAM_RSI_OFF` → `$VEL.CP = WB_approachMPerSec`。

#### f. 層の終わりの位置を記録する

```krl
layerEndPos = $POS_ACT
```

`$POS_ACT` は、今の TCP の**指令位置**（Base[17] 基準）。実測の位置ではない。プログラムの中で読むと先行実行が止まるので、最後の `LIN_REL` が終わってから値が入る。
一時停止から戻るときに、この位置へ戻る。

**この値はプログラムが終わると消える**（`@TODO`。保存先が未定）。残したいときは、プログラムをリセットする前に smartPAD の変数の表示で読む。

#### g. 一時停止（`WB_pauseEnabled = TRUE` で、指定の層のあと）

```krl
aboveEndPos   = layerEndPos
aboveEndPos.Z = layerEndPos.Z + WB_liftZMm

LIN_REL lift C_DIS #BASE          ; 最後の逃げと同じ行
PTP WB_posRetract
PTP WB_posHome

HALT

PTP WB_posRetract                 ; 最初に開始点へ行ったときと同じ道
LIN aboveEndPos
LIN layerEndPos
```

- `HALT` で止まる。スタートキーで `HALT` の次の行から続く
- 止まっている間は、**プログラムをキャンセル・リセット・選び直ししない**。`layerEndPos` はプログラムが動いている間しか無い
- 隔壁は非常停止の回路につながっている。開けたら: 閉める → メッセージを確認 → ドライブ ON → `$IN[400]`（AB System Ready）が TRUE か確認 → スタート
- 止まるのはホームで静止してからなので、`LIN_REL` の途中で止めることにはならない（§4-9 の注意の対象外）
- 最終層のあとでは止まらない（この判定は「最終層以外」の中にある）

#### h. 次の層へ上がって待つ（最終層以外）

```krl
LIN_REL layerStep C_DIS #BASE
WAIT SEC WB_dwellSec
```

Z を 1.40 mm 上げて 30 秒待つ。`WAIT SEC` は先行実行を止めるので、上がったところで止まってから待つ（推察）。

### 4-8. 退避

```krl
LIN_REL lift C_DIS #BASE
PTP WB_posRetract
PTP WB_posHome
```

最終層の終わりから 50 mm 真上へ直線で逃げ、PTP で退避位置、ホームへ戻る。

### 4-9. 中断したときの注意（ヘッダの `RESTART POLICY` / `RESTART CAUTION`）

- **必ず先頭から流す。** 途中の行から選ぶと、動作パラメータの設定と経路の計算が飛ばされる
- 再開の手順: 積めた層を数える → `WB_numLayers` を残りの層数に → `WB_firstPassPlus` を次のビードの向きに → ジョグで実際のビードの天端に合わせて `WB_posStart` を直す → 一時停止の設定を決める → 先頭から流す
- **`LIN_REL` を途中で止めて再開すると、その地点から変位がもう一度まるごと実行され、経路がずれる**（M8）。止めて再開すれば元に戻る、ではない
- 溶接中にエラーで止まったら、そのまま続けない

### 4-10. `WB_ArcOn` / `WB_ArcOff`

ArcTech の ARC ON / ARC OFF。**インラインフォームが展開するのと同じ行**（実機の `teach\line.src` で確認）で、動作だけを「今の位置への長さゼロの `LIN $POS_ACT`」に置き換えてある。
ISC の `WVDepositionRJ.src` の `WeldingAct`（このセルで溶接できた）から写した。**手で書き換えない。**

WorkVisual はこの中の TRIGGER の `ArcGetDelay` / `ArcGetPath` に「The called function … is not hidden」を出すが、誤検出。制御盤は受け付ける。
